## 新安装怎么用

准备 Linux amd64 Ubuntu 24.04／26.04 或 Debian 12／13、依赖下载网络和自己配套的 PVF。两个频道建议至少 8 GiB 内存。然后：

```sh
git clone https://github.com/linux-lixin/dof-easy.git
cd dof-easy
sudo bash dof.sh
```

按菜单选择等级、插件、团本和数据库，填写客户端能访问的 IPv4 与 PVF 路径。原生正式资源随仓库提供，等级程序按锁从 `resources-v1` Release 下载；完整游戏客户端与 PVF 不包含在 Git 中。菜单默认本机构建；高级命令默认拉取自己配置的镜像，源码构建须显式加 `--build`。

菜单默认网页为 `http://服务器IP:18080`，高级命令默认网页仅监听回环地址；以安装结束输出为准。管理员名为 `admin`，初始密码位于实例 `.env` 的 `ADMIN_PASSWORD`。公网访问按 [容器指南](container-installer.md) 设置自己的 HTTPS 入口和安全组。

高级命令、完整参数及模式选择见 [根 README](../README.md)、[容器指南](container-installer.md) 和 [可选宝塔部署](baota-deployment.md)。

## 已有实例怎么管理

```sh
bash dof.sh status --instance main
bash dof.sh logs --instance main --service game --follow
bash dof.sh stop --instance main
bash dof.sh start --instance main
bash dof.sh restart --instance main
bash dof.sh backup --instance main
```

实例保存各自的镜像来源和标签，拉取 Git 代码不会自动更新运行中的容器。已有通用实例更换镜像按安装指南操作，先备份；新等级使用新实例，不通过 `install --level` 改写旧服。

**已有隔离原生网页实例**按 [部署与恢复](dof/deployment.txt) 的显式私有 profile 构建和替换网页；不要重跑首次准备、`init.sql` 或重置玩家库。网页和游戏分别记录提交与镜像，合并源码不触发服务器部署。

原生管理从 `/admin/dof` 进入，账号、角色和活动从后台相应导航进入。修改前读能力提示，使用预览及同一操作编号提交；结果不明时先按编号核对，再决定恢复或重试。配置需保存后回读，恢复冲突不能强行覆盖。PVF 与配套包见 [协议与流程](dof/protocol.txt)，各项实现见 [实施记录](admin/replacement-implementation.md)。

## 开发与验证

Linux 下在仓库根目录运行；原生 Python 检查要求 Python 3.11+：

```sh
python3 -m unittest discover -s tests/unit -p 'test_*.py'
python3 -m unittest discover -s tests/unit/dof -p 'test_*.py'
python3 -m unittest discover -s tests/structure -p 'test_*.py'
cd services/admin/frontend
npm ci
npm run build
cd ../backend
mvn -Dmaven.test.skip=false test
```

Maven 默认跳过测试，验证时必须显式启用。POSIX 权限、Bash 和隔离测试在 WSL／Linux 执行；Windows 直接执行整套 Python 检查不适用。私有输入及一次性 MySQL 契约库缺失时跳过，跳过不计为通过。前提与集成验收见 [测试入口](../tests/README.md)，本次结果见 [阶段验证摘要](validation/stage-2026-10-28.json)。
