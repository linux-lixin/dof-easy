# 活动与经济管理

管理页面按原生表提供配置读取、变更预览、保存及记录核对；接口执行管理员权限和字段白名单检查。
奖励和领取仍由现有游戏组件执行，网页不会另建发奖或结算调度。

签到、战令、收集箱、商店、奖池等模块以当前配套 schema 为准，不能将界面存在视为原生执行等价。
未知或尚未验证的字段保持限制；未启用活动不自动开启。

配套资源预览使用可选本机文件 `DNF_COMPANION_PREVIEW`，未提供时没有条目。
历史导入内容、玩家进度、兑换码、业务测试数据库和验收快照均不进入仓库。

并发、重复兑换、断连后结果核对及游戏效果需在独立合成库和客户端继续验收。

签到等记录遇到 HTTP 409 结构不兼容时必须具体显示缺项，不能将其他配置保存通过扩写为全部活动已通过。网页与原生执行的实际验收范围见 [状态页](../dof/status.md)。

## 装备规则全表文件（S30，本地实现）

继承、回收和跨界模块使用服务端分页（每页 1～100 条）；不带分页参数的旧读取接口仍在超过 1000 条时明确拒绝，避免旧调用者误读截断结果。“导出全表规则”读取完整、按代码递增的规则表，不依赖当前页。导出期间持有规则表和权限表的只读锁以取得一致内容；慢速下载可能延后相应写入，可取消读取以释放连接和锁。

固定接口均要求当前管理员和绑定实例身份：

- `GET /api/v1/admin/activities/{inheritance|recovery|cross-border}?page=1&pageSize=20`
- `GET /api/v1/admin/activities/{inheritance|recovery|cross-border}/dataset/export`
- `POST /api/v1/admin/activities/{inheritance|recovery|cross-border}/dataset/check`，请求体为原始 JSON 文件，最大 256 MiB。

下载为网页格式 `dof-equipment-rules-v1`，包含模块、实例 ID、数据库 UUID、固定字段目录、全部规则、行数和 SHA-256。摘要按服务端固定字段顺序编码头部及每行 JSON，每段后附换行计算；不是文件原始字节摘要或通用 JSON 规范化标准。字段顺序和空白可以重排，行必须保持代码唯一递增。原生 unsigned INT 和旧文本原样保留，不因导出而强制转成当前可写业务参数；无效 UTF-8 和未知表结构明确拒绝。下载中断后文件不完整，校验应失败，不能继续发布或视作备份成功。

“检查文件完整性”只验证网页文件结构、内容摘要与实例绑定。上传期间不持有原生表锁，完成前重新核对管理员权限。它不会生成写入计划、创建业务操作编号、导入配置、清空规则或修改玩家数据。文件通过检查也不表示其中每行可直接用于业务写入。

批量导入、批量清除、持久化父子任务、逐项核对与定向恢复继续待实现；晴空原工具文件格式、菜单行为和默认值留待手动对照。当前服务器仍运行 S29，本节新增接口及页面没有完成真实部署验收。证据见 [S30 检查记录](../validation/admin-equipment-dataset-s30-2026-10-28.json)。
