# 活动与经济管理

管理页面按原生表提供配置读取、变更预览、保存及记录核对；接口执行管理员权限和字段白名单检查。
奖励和领取仍由现有游戏组件执行，网页不会另建发奖或结算调度。

签到、战令、收集箱、商店、奖池等模块以当前配套 schema 为准，不能将界面存在视为原生执行等价。
未知或尚未验证的字段保持限制；未启用活动不自动开启。

配套资源预览使用可选本机文件 `DNF_COMPANION_PREVIEW`，未提供时没有条目。
历史导入内容、玩家进度、兑换码、业务测试数据库和验收快照均不进入仓库。

并发、重复兑换、断连后结果核对及游戏效果需在独立合成库和客户端继续验收。

签到等记录遇到 HTTP 409 结构不兼容时必须具体显示缺项，不能将其他配置保存通过扩写为全部活动已通过。网页与原生执行的实际验收范围见 [状态页](../dof/status.md)。

## 装备规则全表文件（S30，本地实现）

继承、回收和跨界模块使用服务端分页（每页 1～100 条）；不带分页参数的旧读取接口仍在超过 1000 条时明确拒绝，避免旧调用者误读截断结果。“导出全表规则”读取完整、按代码递增的规则表，不依赖当前页。导出期间持有规则表和权限表的只读锁以取得一致内容；慢速下载可能延后相应写入，可取消读取以释放连接和锁。

固定接口均要求当前管理员和绑定实例身份：

- `GET /api/v1/admin/activities/{inheritance|recovery|cross-border}?page=1&pageSize=20`
- `GET /api/v1/admin/activities/{inheritance|recovery|cross-border}/dataset/export`
- `POST /api/v1/admin/activities/{inheritance|recovery|cross-border}/dataset/check`，请求体为原始 JSON 文件，最大 256 MiB。

下载为网页格式 `dof-equipment-rules-v1`，包含模块、实例 ID、数据库 UUID、固定字段目录、全部规则、行数和 SHA-256。摘要按服务端固定字段顺序编码头部及每行 JSON，每段后附换行计算；不是文件原始字节摘要或通用 JSON 规范化标准。字段顺序和空白可以重排，行必须保持代码唯一递增。原生 unsigned INT 和旧文本原样保留，不因导出而强制转成当前可写业务参数；无效 UTF-8 和未知表结构明确拒绝。下载中断后文件不完整，校验应失败，不能继续发布或视作备份成功。

“检查文件完整性”只验证网页文件结构、内容摘要与实例绑定。上传期间不持有原生表锁，完成前重新核对管理员权限。它不会生成写入计划、创建业务操作编号、导入配置、清空规则或修改玩家数据。文件通过检查也不表示其中每行可直接用于业务写入。

S31 已继续接入批量导入、批量清除、持久化父子任务、逐项核对与定向恢复，见下节；晴空原工具文件格式、菜单行为及默认值仍待对照。本节在 S30 当时未部署；S32 已完成继承模块的真实部署和21条规则验收，S33 又补齐回收、跨界的批量配置闭环，见后文。证据见 [S30 检查记录](../validation/admin-equipment-dataset-s30-2026-10-28.json)。

## 批量规则任务（S31 实现，S32～S33 三模块配置已实测）

继承、回收和跨界提供三种独立预览：网页文件按代码新增或更新、清除当前全表、关联恢复原任务已确认完成的项。导入不会删除文件未包含的规则；恢复会保留无关的后续修改，对已重新使用的代码和成组材料冲突拒绝覆盖。文件仍为网页 v1 格式，原 Windows 工具格式和默认行为没有据此取得等价结论。

每个任务保存独立父编号、固定计划摘要、数据库 UUID、预览时全表版本及逐条前后快照。子回执逐条存入既有管理日志，父记录不保存大型行数组，不受单条日志 2 MiB 或旧列表 1000 条上限影响。文件先接收到私有临时目录，检查最大 256 MiB 和基础空间余量，完成后才取得配置锁建立日志计划；计划建立失败时只回滚 InnoDB 管理元数据，原生表不参与预览写入。临时文件在请求结束时删除，重启后执行只依赖已持久化的计划和子回执。

执行每次最多 20 项，由原操作者明确继续。预览即保留当前模块，普通网页写入不能绕过该任务。执行开始前核对全表版本，每条提交前再核对当前行；未决 `PREPARED` 和 `CONFLICT` 子项阻止自动推进。断连或重启后读取原任务和原子项；结果不明时不换编号重写，也不因配置当前值吻合而声称玩家业务效果通过。任务完成时另记当前模块摘要；清除后被外部新增的规则不会被额外删除，页面会显示剩余条数。

取消和冲突确认具有新的控制编号、原因、预览和提交，控制记录可分页读取。取消仅关闭尚未提交的子项，保留成功项及未决项。其他当前管理员可以明确取消并另建关联恢复任务，但不能代原操作者直接继续。人工确认只保留当前值，原结果仍未知；关联恢复不把人工确认或未执行项冒充成功项。

批量接口位于 `/api/v1/admin/activities/{inheritance|recovery|cross-border}/batches`：

- `GET /state` 读取全表版本，`GET /` 读取最近任务，`GET /{id}?page=1&pageSize=20` 读取任务及逐项结果。
- `POST /clear/preview`、`POST /restore/preview` 接收 `requestId`、`revision`、`reason`，恢复另需 `sourceTaskId`。
- `POST /import/preview?requestId=...&revision=...&reason=...` 请求体为原始网页 JSON 文件。
- `POST /{id}/step` 使用当前任务 `revision`；失去回复后先读取原任务，旧版本不能直接推进下一段。
- `GET /{id}/items/{child}` 读取当前值和版本，`POST /{id}/items/{child}/reconcile` 核对已准备的原子项。
- `POST /{id}/controls/preview`、`POST /{id}/controls` 预览和确认 `cancel` 或 `accept-current`；后者要求指定子编号和当前值版本。
- `GET /{id}/controls?page=1&pageSize=20`、`GET /{id}/controls/{control}` 读取控制历史或原编号回执。

页面将任务与控制编号按模块保存在当前会话中，不保存规则快照或上传文件；重载优先显示待处理单条操作，否则返回上次批量模块。执行不会在后台自动重新发起；超时、切换设备或服务重启后从历史读取同一任务。

本地验证和限制见 [S31 检查记录](../validation/admin-equipment-batch-s31-2026-10-28.json)。当前批量快照和计划完整性检查仍需扫描全部子回执；大于已验证 1005 条的耗时、容量和多实例并发须继续验证。S32 已部署同一批量实现并验证继承配置及旧镜像的受控冻结历史，S33 完成回收/跨界批量配置验收；更多容量和物理故障仍待验，不将原有模拟页面、服务对象重建或 SQL 故障注入扩写为真实部署证据。原工具文件对照、消费端和玩家实际效果继续待验。


## S32 真实部署与回退边界

86级绑定实例的 admin 宿主端口为 18080，运行源码 `e8ccd6b`（批量实现 `2a14cd2`）。预构建镜像同时更新两个 Nginx 模板路径，防止旧运行镜像中的优先模板覆盖新路由；超过1MiB的绑定文件检查已通过真实代理。部署保留旧镜像、管理卷、绑定身份及相关字段恢复点，游戏容器未重建。

继承模块使用21个专用规则代码，完成分段导入、未提交项取消、关联恢复、全表清除及恢复，最后恢复原始空表。176条新回执和34条既有装备回执均保留，没有未决装备操作。界面和接口的实际提交响应被验收工具故意遮断后，均通过原编号继续处理；这不等同于物理断网或数据库断电。首次验收工具响应缓存错误同样按原预览继续，没有重新生成任务。S32 当时仅验证了回收和跨界的批量目录读取，S33 后续另行完成了它们的真实批量配置验收。

旧 S29 后端不支持新的批量协议。回退镜像只读提供38个已核对的历史查询快照，每次由旧后端重新验证管理员；匿名、伪令牌及实际撤权后的 GET/HEAD 均被拒绝，专用测试管理员按读取到的原值恢复。所有业务写入关闭，当前配置和任务执行不可用，未快照的分页参数也拒绝，避免把第一页误当成其他页。它是维护用的历史读取桥接，不能代替新版的实时任务管理。

第一次兼容镜像因旧 Nginx 默认映射桶容不下长 UUID 路径而启动失败，已自动回到候选并保留记录；修正桶容量后先在断网容器执行实际 Nginx 语法检查。第二次演练在权限写入前发现旧权限假设不符，未改权限即停止并切回；第三次按真实权限值通过全部检查。当前已回到新版，两个模板和展开配置均为候选原值，历史快照与实时回执再次逐项一致。

完整证据见 [S32 验收记录](../validation/admin-equipment-batch-s32-2026-10-28.json)。原工具手工对照、组件消费、玩家物品及游戏流程仍未通过；其他工作包和多等级验收继续执行。

## S33 回收、跨界及未完成任务重建

同一86级实例继续运行 S32 的镜像，端口保持18080。回收和跨界分别完成21个专用规则的实际网页分段导入、部分取消、清除及关联恢复。回收七字段覆盖额外金币代码0及材料费用；跨界五字段分别保存扣除数量和独立持有下限。各自恢复后的完整文件摘要与原文件一致，最后三个规则表均恢复为空。本次未以继承结果替代其他模块验收。

额外的回收任务先确认20条配置已写入、1条仍未提交，再实际重建同镜像 admin。重新登录、读取原任务后，任务版本、逐项状态及原生规则数据摘要均保持一致，没有自动续写第21项。原编号重放只返回既有进度；旧段版本和新的重复任务编号被拒绝。随后明确取消未提交项，并以独立关联任务恢复那20条已确认写入的配置。

396条新回执逐条核对了操作者和前后快照，之前237条回执的整行摘要不变；重建后另完成30次任务及控制记录读取。部署模型、环境文件、镜像、钱包、奖励、暂停兑换码、密钥、游戏PVF和配置保持原值，游戏容器没有重建。

完整记录见 [S33 验收证据](../validation/admin-equipment-batch-s33-2026-10-28.json)。该重建发生在任务段之间；数据库中断、磁盘不足、进程强退和更新中断仍需验证。原工具格式/默认值对照、组件消费、玩家物品及游戏效果继续待验。S32的旧S29冻结历史镜像仅覆盖S32时点，本次使用仍支持相同批量协议的 e8ccd6b 后端读取新回执；更旧镜像需要重新生成并核对覆盖新记录的历史快照。

固定隔离实例的浏览器验收脚本为 `tests/integration/admin/equipment-batch-live.cjs`，`--section` 仅接受继承、回收、跨界三种固定模块，默认首次运行要求新输出目录和空规则表。`--resume-preview` 只允许核实首个预览已存在后按原号恢复，不能重做种子创建。`tests/integration/admin/equipment-batch-restart-live.py` 是服务器本地的一次性操作测试，依赖已准备的 S33 恢复点和完成的两个浏览器结果；它会拒绝重复运行，并仅重建 admin。凭据、原文件和数据库备份始终留在服务器。

## 原生战力排行榜规则（S36 本地实现）

`charts` 提供已有1号规则的最低上榜战力、奖励间隔和奖励小时编辑。原生编号、排行榜入口、膜拜入口和下次结算时间只读，不支持网页新增、删除或初始化。修改后的奖励间隔至少1天、小时为0～23，按数据库时区解释；历史异常值在未编辑时保留。超出数据库有效日期范围的间隔拒绝保存。

两个入口分别判断：原网关的膜拜奖励读取条件为 `top_index=0 AND is_mobai=1`，不依赖排行榜 `status`。因此规则和奖励的预览、提交及恢复都要求唯一1号配置且 `status=0 AND is_mobai=0`，并在表锁内重查管理员及两个入口。排行榜配置表另核对七字段、索引、触发器和外键；奖励目标表的完整结构与副作用检查仍需单独补齐，不能据此验收整个奖励管理。排行榜关闭而膜拜仍开时不能改写奖励。网页不会停用或启用入口，也不新增排名、调度或奖励执行器。

保存周期不会重新计算 `next_time`。阈值的定向恢复保留后续原生结算时间；恢复周期或小时属于成组恢复，如果周期、小时或 `next_time` 已被其他操作改动，拒绝覆盖。预览、持久化编号、重复提交、版本冲突、结果核对和恢复沿用现有活动协议，MyISAM 写后断连先核对原编号。

该实现尚未部署到86级实例；本批只读确认真实七字段结构以及两个入口均已开启，没有改动现有玩法。原工具菜单、默认值、启停操作、运行时读取时机、实际排名、结算和奖励效果仍待验证。证据与失败记录见 [S36 验证记录](../validation/admin-native-charts-s36-2026-10-28.json)。
