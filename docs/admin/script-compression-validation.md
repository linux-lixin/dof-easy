# 压缩 Script 的离线核对

压缩索引编解码已经接入整文件比较，但网页生成任务当前仍使用不压缩参数。原工具压缩参数的首字段与压缩索引长度有关，不能用 `1` 代替，也不能仅凭压缩文件可解包就开放发布。

`scripts/dof/audit_compressed_script.py` 是独立 Python 核对工具，不加载或执行 Windows 代码，不连接数据库，不写入 PVF 或参数。它需要原始标准 PVF、原工具生成的压缩文件、两者已记录的 SHA-256，以及来源锁中匹配的原始 `ijl15.dll`。派生客户端 DLL 有独立版本锁，不能拿它替代这里的原始来源。

```bash
python3 scripts/dof/audit_compressed_script.py \
  --source /absolute/path/original/Script.pvf \
  --candidate /absolute/path/native-compressed/Script.pvf \
  --source-sha256 SOURCE_SHA256 \
  --candidate-sha256 CANDIDATE_SHA256 \
  --client /absolute/path/original/ijl15.dll
```

检查包括头部与标准 PVF 版本、一个有界 zlib 索引流、全部索引字的同一转换关系、全部资源字节、完整1280字节尾部、文件边界以及两份全文件哈希。它采用流式读取，不生成明文副本，结束时重新检查输入文件身份、长度和修改时间。失败不会修改输入，也不会输出内容参数或掩码。

若需要验证原工具保存的配对参数，在参数所在主机执行同一检查，并添加 `--parameter-file /absolute/path/parameters.private`。文件只包含原始 ASCII 参数正文，保留服务器本地0600权限；不要发送到聊天或提交到仓库。工具核对上下文和数字参数是否确实对应这份压缩产物，另外报告首字段是否符合当前候选关系。未提供该文件时，`pairedNumericParameterVerified` 为 `false`，`compressedMarkerHypothesisMatched` 为 `null`。核对通过也始终返回 `publishable: false`，不自动生成、应用或发布参数。

当前候选关系为：对公开格式常量 `jmc` 使用 `geah` 上下文形成文本包络，将所得十六进制解释为整数，取十进制末8位41444171，再与压缩索引字节数异或。它符合保留的12组离线浮点模式记录中的8组；另4组不符。所有这些记录都没有验证真实运行上下文，不能只选匹配组就认定协议完成。本轮没有重新运行原程序或重放这些原始指令。

S35 使用保留的真实原工具压缩文件核对了82583080字节原索引、38262851字节压缩索引及482630201字节资源，完整文件通过；这份样本缺少配对的压缩参数，因此首字段关系仍未验证。5项合成拒绝测试用于检查损坏、尾随数据、错误参数及错误版本的拒绝行为，单独记录，不替代真实原工具样本。

后续需由原工具手工对照取得同一批次的文件和配对参数，在隔离环境核对，再验证匹配组件实际读取和游戏效果。原工具与网页不得同时修改同一份测试数据。完整记录见 [S35 验证记录](../validation/admin-script-compression-s35-2026-10-28.json)。

本批还显式提供本地私有样本，执行4类 Java 测试共25项，零失败、零跳过；其中5项有条件的样本检查实际执行。它包含保留的原工具完整文件及旧离线生产端向量，不能把所有25项统称为原 GUI 对照。标准 Maven 重新编译的331个主类文件与 S32 输出逐字节一致；这不是独立干净工作区或最终镜像的复现验收。
