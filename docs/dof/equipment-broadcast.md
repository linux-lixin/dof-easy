# Dof 装备广播实现

实现位于 `services/game/runtime/ubuntu/gateway/equipment.js`，由正式资源构建器纳入哈希清单。它是项目新增的实现，使用固定免授权插件的原生接口；没有从非免授权程序复制广播代码，也没有修改授权逻辑。

## 默认规则

配置文件为 `/data/dof-easy/config/equipment.json`。默认启用，广播当前游戏频道内状态至少为 3 的玩家；史诗品质编号为 4，消息为 `恭喜玩家【角色名】获得【装备名】×数量！`。不跨频道转发，也不修改物品或发奖励。

- `rarities`：允许的品质编号，默认 `[4]`。
- `itemIds`：额外允许的装备编号，默认空；即使在白名单中，可堆叠道具仍不广播。
- `cooldownMs`：同角色发送间隔，默认 3000 毫秒。
- `duplicateMs`：相同角色、物品、数量的重复事件窗口，默认 1000 毫秒。
- `maxPerMinute`：当前游戏进程每分钟最多发送数量，默认 20。
- `enabled`：布尔开关；`scope` 当前只接受 `channel`。

过滤和限流只影响广播，不影响正常拾取。配置在启动时读取；未知字段、非法类型或不支持的范围会导致启动明确失败，不回退到旧配置。规则变化需要按对应部署入口重启目标实例，修改网页配置不等于游戏已重新读取。

## 原生接入

已对本地游戏二进制确认：`CParty::get_item` 在 `CInventory::insertItemIntoInventory` 返回失败时提前退出；后续拾取错误也提前退出。成功分支在 `0x085a6228` 调用 `_onGetItem`，广播观察器在这个完成回调返回后执行，不拦截原函数或更改返回值。

`scripts/dof/native_equipment.py` 为缺失的 `DBMgr::Equipment_Broadcast(CUser*, int, int)` 定义真实原生入口。入口代码位于新增 RX 段，派发指针位于 RW 数据；启动时注册同一套广播实现。原生入口与拾取观察器共用过滤和去重，避免同时触发时重复公告。派发未注册时会触发明确错误，不以空函数假装完成。启动时同时校验桥接字节、符号地址和游戏回调指令，拒绝未知 ABI。

项目原生模式已经使用 Gadget 处理数据库凭据；广播复用这一运行环境。DP2-only 模式也会加载这部分服务端实现，无需启用普通 Frida 功能脚本。是否覆盖其他游戏版本，仍以逐版本 ABI 和真实运行结果为准。

实现兼容配套 Gadget 的旧 JavaScript 引擎，不依赖 `Set`、`Map` 或 `Number.isInteger`。公告使用当前游戏线程的 PacketPool；构造后未取得缓冲区时返回错误并记录日志，不调用需要有效缓冲区的组包函数或析构器，也不把失败计为已发送。

## 验收范围

规则单元测试覆盖品质、白名单、非装备、无效参数、消息、重复事件、角色冷却、频道限流、禁用和配置错误。原生指令测试覆盖两个加载基址下的参数、栈、寄存器和未注册拒绝行为。

真实进程探针使用实际 PVF 数据、真实 CUser 构造、原生导出调用和完成回调，观察标准公告组包及频道发送函数。旧 Gadget 会抑制嵌套 Interceptor 观察，因此测试使用临时原生入口观察器，保留原指令与真实发送过程；完成回调由后续游戏线程中的原生调用触发。探针和测试角色只存在于隔离测试输入，不进入安装包。

构造的测试角色不等于玩家登录，直接调用完成回调不等于从掉落到入包的完整拾取。空频道发送函数被调用也不等于客户端已收到并显示。客户端显示与完整玩家拾取不得据此标记通过。当前只针对固定 86 级测试版本，未开展全版本矩阵。最新结果见 [状态页](status.md) 和 [运行摘要](server-runtime-validation.json)。
