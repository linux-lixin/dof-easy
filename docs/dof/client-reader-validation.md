# 客户端格式 2：读取适配与验收

本页记录客户端格式 2 的代码与测试状态。代码合并不表示已更新服务器或已经进游戏。原始配套保存在操作者本机，测试在完整客户端副本中进行。

## 正式派生入口

`scripts/dof/client_reader.py` 接受固定 SHA-256 的免授权登录器或 `ijl15.dll`，分别输出 `dof-launcher.exe` 和 `ijl15.dll`。配方 `dof-launcher-reader-2.1` 增加只读字符串区与可执行适配区，不增加永久可写可执行段，不移动原有节、导入、重定位、TLS 或入口点。

适配覆盖实际文件存在检查、字符串长度／复制来源、字段比较和原生配置查询入口。长文件名放入新增存储空间；被保护代码恢复的引用在消费入口重定向。原生查询函数检查 `token_dof_version=2`；缺失或不匹配时显示错误并停止。原有初始化及保护分支保留。

`scripts/protocol/dof/prepare_client_inputs.py` 把派生器、显式旧模板导入和新格式校验串起来，输出网页的私有输入。正常网页生成仅接受新字段、新文件名和版本 2。输入准备与安装命令见 [部署说明](deployment.txt)。

| 输出 | SHA-256 |
|---|---|
| `dof-launcher.exe` | `91aaec7a480ffd90d0feebb8aad9c82d0199f0599c6660125d053e2dbda19cd6` |
| `ijl15.dll` | `0f7f022f38f2dd4e7d2f4f0805c2ab8cb9b8a76303ffec2cbffa102e5d2f308e` |

这些哈希绑定当前读取适配；完整游戏协议与资源链尚未通过，不能据此宣称完整客户端发布就绪。后续二进制变化必须同步锁值并重跑受影响检查。

## 2026-10-26 已取得的证据

| 检查 | 结果与边界 |
|---|---|
| 完整客户端副本 | 配套依赖齐全；原始客户端不变 |
| 确定性与 PE 布局 | 两个固定输入重复派生哈希一致；原始节仅修改列出的指令窗口；导入、重定位、TLS 和入口保留 |
| i386 调用约定 | 文件名、比较双方、长度／复制来源、原生 getter 的寄存器与栈回归通过 |
| 登录器真实读取 | 无适配注入、无旧名配置文件；读取 `dof-client.dll` 和新字段后发起连接 |
| 错误／缺失格式版本 | 两个真实测试均显示明确错误，未观察到连接请求 |
| 游戏 DLL 加载 | 实际 `DNF.exe` 加载派生 DLL，基址发生重定位；直接启动提示必须通过登录器，未绕过该检查 |
| 目标测试服连接 | 新登录器 TCP 8887 连接成功；不等于账号登录或进游戏 |
| 网页账号 | 通过网页注册接口创建普通联调账号，并通过网页登录验证；凭据仅在本地私有材料中保存 |

观察脚本只记录文件名、字段名、长度、模块和网络结果。正常联网测试只允许已确认测试服的游戏端口；离线正反测试阻断全部网络。日志、私有配置、完整客户端、账号密码及转储不入库。

## 尚未通过的项目

- 游戏 DLL 在登录器正常启动链中的完整配置读取、控制消息和公钥消费。
- 剩余内部品牌语义、`<dof>`／`dofRobotc`／`dof_config` 消费和 PVF 资源路径适配。
- 从已合入 main 的网页产物生成、应用并下载同批次配套包。
- 登录、选角、进城、普通地下城、返城、重登；装备广播、随机盒和两个团本分别验收。

`READY_FOR_TEST` 仅表示产物待验收。服务端启动的既有通过记录、离线算术测试和端口连通均不替代上述项目。
