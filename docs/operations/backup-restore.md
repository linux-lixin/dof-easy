# 备份与恢复

## 创建备份

在仓库根目录执行：

```bash
sudo bash dof.sh backup --instance qingkong86
```

备份会核对外置数据库身份，暂时停止本实例正在运行的游戏服务，然后使用游戏账号导出项目游戏库和 `qk`。完成或失败后会尝试恢复原本运行的游戏服务；备份后仍应检查状态：

```bash
sudo bash dof.sh status --instance qingkong86
```

输出位于 `.dof-easy/backups/`，具体归档名以命令输出为准，同时生成 `.sha256` 校验文件。备份权限受限，因为其中包含密码和私钥。

## 备份包含与不包含的内容

| 内容 | 是否在实例备份中 |
|---|---|
| 项目游戏库和 `qk` 的 SQL 导出 | 包含 |
| 实例配置、密钥、PVF、晴空文件和运行数据 | 包含 |
| 服务器上的源码版本和 Docker 镜像 | 不包含，需要记录提交及保留旧镜像 |
| MySQL 系统账号、Host 授权、root 密码 | 不包含，需要另行私下保存管理记录 |
| 宿主机管理员客户端配置、宝塔和云防火墙设置 | 不包含，需要单独保管 |

实例文件和对应数据库必须作为同一份身份保存。不要把另一台服务器的私钥或其他实例配置拼接进来。备份、SQL、私钥与原始日志都不提交 Git。

## 如何检查备份

先核对同名 `.sha256` 文件与归档校验和，再确认归档中有 `databases.sql`、实例配置、PVF 和密钥。归档存在、校验和匹配，只能证明备份文件生成完整；还需要在隔离环境中测试 SQL 导入和恢复后的服务启动。

## 恢复流程

当前没有一键恢复命令，恢复按以下顺序人工处理：

1. 保留当前现场副本，确认要恢复的实例、源码提交、镜像与备份属于同一套服务。
2. 先在隔离的 MySQL 5.6 环境中验证 SQL 可导入，不直接用线上玩家库试错。
3. 停止目标游戏实例，再恢复对应数据库和实例目录；核对数据库账号、Host 授权、连接配置与密钥。
4. 如果换过 MySQL 服务，重新核对 UUID 绑定和目标库；不要只修改标记骗过身份检查。
5. 使用匹配的源码与镜像启动，检查网关、频道、后台连接和客户端登录。

当前只验证过备份校验和及 SQL、PVF、密钥存在性，尚未完成完整灾备恢复演练。详细范围见[验证状态](../status/README.md)。
