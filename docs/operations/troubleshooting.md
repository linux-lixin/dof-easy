# 排错指南

先确认问题发生在哪一步：安装、服务启动、后台数据库连接，还是玩家登录。不同阶段使用的地址和账号不一样。

## 先看实例状态

在仓库根目录执行：

```bash
sudo bash dof.sh status --instance qingkong86
sudo bash dof.sh logs --instance qingkong86 --service game
```

新启动的频道需要加载 PVF。`keys` 容器是一次性初始化任务，`Exited (0)` 正常；game 容器应最终进入 `healthy`。日志和配置可能含私有信息，分享前遮盖密码、密钥和玩家数据。

## 按现象处理

| 现象 | 先检查什么 | 下一步 |
|---|---|---|
| 晴空输入校验失败 | 是否为匹配原包，12 个二进制与 5 个配置是否齐全 | 按[安装材料](qingkong-baota.md#2-准备配套文件)补齐，不改哈希跳过校验 |
| 已有库或 game 账号冲突 | 是否误对已有服执行首次初始化 | 确认实例归属，已有服走[升级流程](upgrade.md)，不直接删库 |
| 镜像拉取失败、标签不存在 | 是否明确拥有包含当前修改的发布镜像 | 使用源码构建；离线方式不会自动补下载 |
| Docker context 被拒绝 | 是否配置了远程或非默认 Docker context | 使用本机默认 Docker，按提示处理环境变量 |
| 内部密码提示必须 8 位 | 是否把后台长密码填入运行配置 | 阅读[密码说明](daily-management.md#数据库密码与密钥)，不要删校验或静默截断 |
| 外置数据库 UUID 或绑定不一致 | 是否连错数据库或更改了实例连接身份 | 核对地址、UUID 和授权，不删除绑定标记 |
| 密钥不一致 | 是否混用了其他实例文件或重新生成了密钥 | 保留现场，找回同一实例完整密钥，不删密钥重试 |
| 旧登录模式被拒绝 | 是否在用旧 dof/native/internal 实例 | 按[分支说明](upgrade.md)返回原 main 备份维护 |

## MySQL 连接问题

- **超时或连接拒绝**：核对访问地址、MySQL 监听、3306 端口、宿主机防火墙及云安全组。Windows 公网连接不能直接使用宿主机私网 IP；游戏容器不能把自身的 `127.0.0.1` 当作宝塔数据库。
- **1045 / Access denied**：核对用户名、密码和来源 Host。MySQL 会先匹配来源账号，两个同名 `game` 的密码不一定相同；更具体的来源匹配失败不会回退到 `%`。
- **能连接但操作提示权限不足**：只给 `qk` 权限不能管理全部账号和角色。核对[项目游戏库授权范围](external-mysql.md#数据库账号如何区分)，不要直接换成公网 root。
- **root 公网登录失败**：如果已设置 root 仅本地登录，这是预期行为。后台应使用授权的游戏库账号；宝塔通过本机管理员连接。

## 容器健康，但进不了游戏

按顺序检查：

1. 原版登录器是否连接了正确公网 IP 和网关 TCP 8887，而不是 MySQL 3306。
2. 登录器公钥是否来自当前实例，客户端与服务端 PVF、补丁是否配套。
3. 频道列表、relay 和具体频道的 TCP/UDP 是否按[端口表](../reference/ports.md)放行。
4. 使用的是否为游戏账号；数据库账号和 SSH 账号不能用于玩家登录。
5. 分别记录卡在登录、选角、进城、进图还是重登，再检查对应日志。

公网 TCP 可达不能证明公网 UDP 游戏流量正常。服务器侧检查和客户端操作的验证范围见[验证状态](../status/README.md)。
