# Windows 晴空后台与登录器

后台工具管理服务器数据，玩家登录器连接游戏网关；它们使用的连接参数不同。使用与服务器同一套来源的晴空原版工具和配套文件。

## 后台工具：数据库连接

如果后台界面要求“数据库地址、端口、账号、密码”，填写的是 MySQL 连接，不能填游戏网关端口。

| 字段 | 填写内容 |
|---|---|
| 地址 | Windows 能访问的数据库地址；公网直连时通常为服务器公网 IP |
| 端口 | MySQL 实际端口，默认 3306 |
| 用户名 | 已授予后台管理权限的数据库账号，例如 `game` |
| 密码 | 与该来源账号匹配的数据库密码 |
| 数据库（若界面要求） | 晴空配置使用 `qk`；账号、角色管理还需要相关游戏库权限 |

安装器创建的内部 `game` 账号只允许指定 Docker 网段访问，Windows 不能直接借用该授权。外部后台连接需要由管理员另行创建或授权，安装器不会自动开放公网后台账号。来源匹配、同名账号和权限范围见[数据库指南](external-mysql.md)。

连接方式可以是公网直连，也可以是 SSH 隧道。直连需要服务器监听、宿主机防火墙、云安全组和 MySQL 来源授权共同允许连接；宿主机私网 IP 通常不能从 Windows 公网直接访问。如果使用隧道，后台填写本地转发地址和端口。不要把后台数据库凭据分发给玩家。

只授予 `qk` 权限可能足够读取晴空配置，但不足以管理所有账号和角色。后台管理所需权限应覆盖本实例的游戏库清单；账号位于 `d_taiwan`，主要角色数据位于 `taiwan_cain`，相关物品、日志等分布在其他项目库。不要将“连接成功”等同于全部功能权限已齐全。

## 玩家登录器：网关连接

| 配置 | 来源 |
|---|---|
| 服务器 IP | 实例配置的公网 IP |
| 晴空网关端口 | TCP 8887 |
| 登录公钥 | 实例 `client/publickey.pem` |
| 频道与端口 | 实例 `client/qingkong-endpoints.json` 和[端口表](../reference/ports.md) |
| 游戏资源 | 与服务端一致的 PVF、匹配的完整客户端和晴空配套补丁 |

`qingkong-endpoints.json` 是信息导出，不是原版登录器配置格式。按实际原版工具界面设置 IP、网关和公钥；当前尚未完成 Windows 工具逐字段操作验收，不在这里假定菜单名称或生成步骤。

配套压缩包中的“客户端文件”不等于完整客户端。将同一配套的启动器、DLL、补丁等用于匹配的完整客户端，保持 PVF 一致。不要把派生登录器或其他版本的配置格式混入本分支，也不要重新生成一套与服务器不匹配的密钥。

## 分阶段检查

1. 后台：数据库连接成功，能够读取晴空配置和账号、角色数据。
2. 登录器：能连接网关，使用的是游戏账号，不是 MySQL 或 SSH 账号。
3. 游戏：完成注册/登录、选角、进城、进图、返城和重登。

数据库认证、公网端口和容器健康均不能代替第三步。当前实测范围见[验证状态](../status/README.md)，故障定位见[排错指南](troubleshooting.md)。
