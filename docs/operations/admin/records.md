# 记录查询与只读诊断

用途与读者：运维与开发人员。适用范围：绑定原生管理实例，只读操作。前置条件与操作见正文，执行后核对成功信号；历史证据不代表本次重新执行。

事实来源：[DofAdminController.java](../../../services/admin/backend/src/main/java/com/aiyi/game/dnfserver/controller/DofAdminController.java)；[main-deployment-2026-10-28.json](../../validation/main-deployment-2026-10-28.json)。限制和当前验收边界见[当前状态](../../status/README.md)。


进入 `/admin/dof` 的记录模块。先选择固定视图，确认账号/角色与周期；下拉框列出当前视图允许的筛选列，不接受任意表名、字段或 SQL。当前部署目录有 30 个视图。

1. 使用视图默认列输入查询文本，显式查询从第一页开始。中文、通配符文字按接口定义作为文本处理。
2. 切换对象或周期会清空上次结果和分页；切换搜索列保留文本；清空条件同时移除激活条件。
3. 后端 `hasMore` 决定下一页，空表禁用下一页；遇到后端 400 显示错误并清除旧分页，修正条件后再查。
4. 使用只读结构诊断确认缺表、缺列与适配原因；诊断不建表、不写玩家数据。

成功信号：所有记录请求保持 GET、管理员认证通过，查询对象与分页一致。匿名目录、查询、诊断均拒绝。最新部署签到 `signin-users` 返回 200，取样为空；历史 409 的原因仍未知。S46 的筛选与分页代码已包含在后续 main 部署，不能继续写“尚未部署”。

限制：空表样本不证明有数据的分页、原生编码或原工具等价；完整对照仍待验。字段与协议查[API 参考](../../reference/admin-api.md)。失败处理：修正固定字段或绑定结构，不调用任意 SQL 绕过限制。
