# 活动、装备规则与排行榜操作

用途与读者：已绑定后台的管理员。适用：当前能力开放的原生活动、装备和排行模块；后台登录模式不等于所有模块均可用。前提是管理员认证、数据库 UUID、模块结构和权限均通过；先准备该操作的恢复点。

事实来源：[活动控制器](../../../services/admin/backend/src/main/java/com/aiyi/game/dnfserver/controller/ActivityConfigController.java)、[S42 配置证据](../../validation/admin-native-charts-config-s42-2026-10-28.json)与[当前部署](../../status/deployment.md)。字段、协议和限制统一见[活动 API 参考](../../reference/admin-activities.md)。

## 操作顺序

1. 进入 `/admin/dof` 对应活动模块，核对目标、周期与当前版本；先读取，不直接保存。
2. 修改意图先预览，检查差异、目标及恢复范围。确认后按同一 requestId/revision 保存；取消预览不等于恢复已提交操作。
3. 保存后检查回执和回读。断连或状态不明先读取原任务/reconcile，不换编号盲目重发。
4. 需要撤回时依据原回执做定向恢复；冲突先核对第三方修改，不覆盖无关后续进度。

## 装备单条与批量规则

继承、回收、跨界分别选择模块。分页读规则；“导出全表”导出完整网页 v1 文件，不是当前页。导出可能持有只读锁，慢下载可延后写入，必要时取消。上传先做“检查文件完整性”；通过只表示格式、摘要和实例匹配，不写入规则。

批量导入按代码新增或更新，不删除文件未含规则。清除全表与关联恢复分别预览，核对范围后提交父任务。每次最多执行 20 项，由原操作者明确继续；遇 PREPARED/CONFLICT 先处理，不能自动推进。取消只关闭未提交项，保留已成功和未决项；其他管理员可明确取消、另建关联恢复，不能冒充原操作者继续执行。

页面只在会话保存任务编号，不保存全表快照；切换设备或服务重启后从历史读取原任务。大于既有 1005 条样本的容量、耗时、多实例并发和执行段内物理退出仍待验。原工具文件格式与默认行为不因网页格式通过而取得等价结论。

## 排行与奖励

编辑已有 1 号规则的最低战力、奖励间隔与小时；不在网页新增、删除或初始化原生规则。间隔至少 1 天，小时 0～23，按数据库时区解释；原编号、入口和下次结算时间只读。排行榜与膜拜入口独立判断，任何一个开放都应按参考定义处理写入限制。

奖励按原生目标表与当前周期预览、保存和定向恢复；长字段不得按前端展示截断。S42 已验证配置写入、恢复和 admin 重建，后续 main 已包含对应实现；不再写“尚未部署”或“需先修复再部署”。网页不会自动停游戏、关闭入口或执行发奖，不能把受控验收脚本的行为当作产品功能。

## 成功与失败

成功信号为当前操作的持久化、回读和对应恢复记录；`PERSISTED` 不代表组件刷新、玩家物品、实际排行结算、奖励或团本效果。版本冲突先重新读和预览，未决先核对。原工具完整对照、组件消费、真实游戏效果及更多故障仍待验。
