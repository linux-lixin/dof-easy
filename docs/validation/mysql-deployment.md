3 个跳过项分别是需要 Docker Engine 的网络防火墙测试、绑定旧 `vipai86-audit` 容器的历史 MySQL 测试，以及需要 PATH 中 Node.js 的既有 Frida JS 测试。新 MySQL 集成测试独立运行并通过，没有冒充跳过的历史测试已通过。

本地没有可用 Docker Engine，因此**没有重新构建完整 Docker 镜像、执行 Compose 启动或验证宝塔实际 Nginx 配置**。新增镜像阶段使用固定摘要的 MySQL 5.6 镜像，COPY 的备份客户端已在本地从对应层提取、校验 SHA-256，并用于真实备份恢复；这仍不等同于 Docker build 已通过。Nginx 提供配置示例，部署时需在宝塔检查并应用。

本轮不把数据库与网页接口通过，写成原生游戏已在外置数据库上启动或玩家已进游戏。完整登录、装备广播、随机盒、两个团本继续沿用 [整体状态](../dof/status.md) 的下一阶段待验证结论，`releaseReady=false`。

## 复现

具体材料与命令见 [本地集成测试说明](../../tests/integration/mysql/README.md)。测试输出目录必须不存在；所有数据库与网页进程运行在新建网络命名空间，不能访问现有服务器。真实 MySQL 测试会创建并修改一次性测试库，不能直接拿已有数据库路径作为输出。

本轮修复过的实际故障包括 MySQL 5.6 `INSERT … SELECT … WHERE` 需要 `FROM DUAL`、初始账号字段不一致、桥接 `d_channel_cain` 缺失，以及较新 MariaDB dump 对 MySQL 5.6 的元数据不兼容。最终结果来自修复后的正式代码，不使用仅供实验的替代实现。
