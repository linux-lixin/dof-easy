# 容器一键端

在 Ubuntu 24.04／26.04、Debian 12／13 的 amd64 / systemd 主机使用。只管理本机默认 Docker；拒绝远程 context、`DOCKER_HOST` 和 `DOCKER_CONTEXT`。本轮开发与测试不连接现有服务器。

## 三步安装

1. 把项目代码和自己的完整 PVF、固定免授权服务端材料放到主机。可上传源码归档，或在已有 Git 的主机运行 `git clone https://github.com/linux-lixin/dof-easy.git`。
2. 在项目目录执行 `sudo bash install.sh`，选 **1 安装服务端**。
3. 按向导选择并核对最终确认页，输入 `y` 执行。成功后按输出地址登录网页，账号 `admin`，密码在该实例私有 `.env` 的 `ADMIN_PASSWORD`。

```sh
cd /opt/dof-easy # 换成自己的项目目录
sudo bash install.sh
# 等价菜单入口
sudo bash dof.sh
```

缺少 Python 时先询问是否从系统源安装菜单运行依赖；其余主机变更集中到安装确认之后。脚本不会安装宝塔或宿主机 Nginx，不自动重启主机。缺少系统包从 APT 安装，Docker 使用官方签名源；已有引擎复用，同来源补齐缺少的 Compose/Buildx。若补齐需要升级或移除现有软件包，则停止并显示原因。

## 向导选择

| 项目 | 默认与含义 |
|---|---|
| 实例 | `main`，可在菜单 11 切换；每个实例独立配置 |
| 等级 | 86；列表来自锁文件，支持 55/60/65/70/75/80/85/86/90/95/100/110/120 |
| 登录 | 菜单使用 `native`，固定免授权材料；高级命令仍保留 `dof` 模式 |
| 普通插件 | DP2＋Frida，可选择仅 DP2、仅 Frida、关闭 |
| 团本扩展 | 新装默认开启，需要 DP2；已有关闭状态不会自动开启 |
| 频道 | `15,52`，可修改；少于 8 GiB 内存建议减少频道 |
| 数据库 | 内置；也可同机外置 MySQL 5.6，普通安装或宝塔安装均可 |
| 镜像 | 本机构建；可选择自己的仓库，失败不自动切换来源 |
| 网页 | `0.0.0.0:18080`，可修改端口或仅 `127.0.0.1` 监听 |
| 防火墙 | 关闭检测到的 UFW/firewalld，可选择保留 |
| Swap | 根据内存建议补足总量，确认前可修改，0 跳过 |

提供客户端实际可达的 IPv4，NAT 主机可填写公网映射地址。选择的等级仍需与 PVF、客户端匹配；原生 ABI 不匹配会拒绝部署，等级列表不是全玩法通过清单。

资源目录可以是固定免授权原始材料或正式派生结果。原始材料只经确定性派生器转换，正式结果逐文件校验哈希；不接受授权版回退。既有实例再次“安装”仅沿用配置启动，不覆盖数据。

## MySQL 与网页

内置数据库独立容器/卷，不发布宿主机 3306。外置只支持同机 MySQL 5.6，向导输入本机实际私网 IP、端口、客户端绝对路径、socket 和临时管理员密码。客户端自动探测系统、`/usr/local/mysql`、宝塔安装位置。

外置要求尚无本项目库及 `game` 账号；不能通过重新安装接管不明数据库。需 `max_allowed_packet >= 64M`，兼容零日期的 `sql_mode`（例如 `NO_ENGINE_SUBSTITUTION`）。不要为了部署覆盖其他应用需要的配置。管理密码只写安装期间的 0600 临时文件，结束后清除；运行期使用限定到项目库与容器来源的账号。

关闭防火墙前必须让 MySQL 只监听所选私网地址；监听 `0.0.0.0` / `::` 时应改绑定或选择保留防火墙。保留防火墙时，为向导显示的容器网段允许访问 MySQL 私网端口。UUID、版本、权限检查失败不会自动清库。

网页有容器内 Nginx。直接访问 `http://服务器IP:18080`；需要域名/HTTPS 时使用自己的反代。菜单 10 生成 `nginx-location.conf.example`，可用于普通 Nginx 或宝塔，不覆盖已有文件。配置保存、PVF 处理、配套包生成从网页进行。

## 主机准备与恢复

| 物理内存 | 推荐总 Swap |
|---|---|
| <2 GiB | 阻止游戏部署 |
| 2～<4 GiB | 8 GiB；选择预构建镜像 |
| 4～<8 GiB | 4 GiB |
| ≥8 GiB | 2 GiB |

只补足超过已有活动 Swap 的部分。新文件在 `/var/lib/dof-easy/swap/`，权限 0600；支持 ext4/XFS。启用确认后向 `/etc/fstab` 添加带 `# dof-easy` 的独立条目；原件保存在 `/var/lib/dof-easy/host/fstab.before`。恢复时不整体覆盖 fstab，菜单 8 只移除记录内的文件；`swapoff` 失败则保留文件和配置。启用后写 fstab 中断，再次补足会先修复记录，不重复分配文件。

磁盘预算：构建预留 20 GiB、拉取预留 10 GiB，另加 3 份 PVF、新增 Swap、2 GiB 余量；按项目、Docker 数据目录和 Swap 所在文件系统分别累计。该预算是预检，仍可能因后续镜像或备份增长需要更多空间。

新主机先处理防火墙，再安装 Docker，避免引擎创建规则后再关闭 firewalld。防火墙关闭前记录原服务状态并保存配置，菜单 9 可恢复。检测到多个活动管理器时拒绝自动关闭。关闭前后比对 Docker 规则；变化则尝试恢复原防火墙服务并报错，不全局重置规则。自定义 iptables/nftables、云安全组及其他防火墙不自动接管。菜单显示未发现 UFW/firewalld 不代表网络已全部放通。

**firewalld 限制**：Debian 12 实测表明，它的启停可能清理已有 iptables 链。检测到 Docker 或其他自定义 legacy 规则时，脚本在改动服务前拒绝关闭；恢复时如果需要启动 firewalld，同样先检查。此时应选择保留防火墙并按端口放行，不能为了关闭它清空规则或重启已有 Docker。UFW 的关闭与恢复已在运行 Docker 容器时实测。

恢复防火墙状态后仍应检查 SSH 与容器端口。配置快照供人工比对，不盲目覆盖期间用户改过的规则。主机日志和恢复记录在 `/var/lib/dof-easy/host/`，项目阶段记录在 `.dof-easy/operations/`；二者不会写入 Git。

## 日常操作

- 菜单 2 只启停选定实例；重启不等于重启主机。
- 菜单 3 显示实际 Compose 状态和游戏/网页日志。
- 菜单 4 改 IP、频道、玩家来源、网页绑定；菜单 5 独立调整插件和团本。关闭普通插件保留原生登录所需组件。配置变更保存恢复点并应用到实例。
- 菜单 6 备份会暂时停止该实例的写入服务，完成后恢复原来运行的服务。备份含数据库、密钥、配置、PVF 和日志，必须私有保存；列表重新计算 SHA256 与原始摘要比较。旧备份无摘要时明确显示“无原始摘要”。
- 备份/恢复不包含通用 SQL 导入、自动清档或远程上传功能。

初始化失败时保留现场。先看阶段记录、游戏/网页日志和数据库初始化记录；不要删除初始化标记强行重灌。主机已完成操作不会随游戏构建失败自动撤销，可按菜单 8/9 分别恢复。项目未上线时，可另建不同实例进行空库安装；外置库已部分建立时需先人工核对对应库，不能覆盖其他数据库。

端口输出随频道生成：TCP/UDP 7001、7300；UDP 2311～2313；每频道 TCP `30000+频道`、UDP `31000+频道`；原生 TCP 8887；网页默认 TCP 18080。仅开放所需来源，数据库无需公网开放。

## 验收边界

安装成功表示部署检查通过，不代表客户端实际进游戏已通过。登录、选角、进城、普通副本、装备广播、随机盒和团本应使用配套客户端另行验收。实际本轮执行结果见 [一键端验证记录](validation/container-installer.md)。

依赖安装参考 Docker 官方 [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) 与 [Debian](https://docs.docker.com/engine/install/debian/) 文档。
